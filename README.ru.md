# WinOptimize

[English](README.md) | **Русский**

Инструментарий оптимизации Windows на основе фактических данных, собранный в одном PowerShell-скрипте (`optimize.ps1`).
Он проводит аудит, объясняет, оптимизирует — и умеет отменить каждое своё изменение.

> **Главное правило:** никаких слепых твиков. Каждая оптимизация измеряется, проверяется после применения и обратима.

## 1. Обзор и философия

WinOptimize построен на трёх принципах:

- **Диагностика до изменений.** Движок аудита собирает полный фактический снимок системы (ОС, CPU, GPU, RAM, диски, сеть, службы, реестр, питание, автозагрузка, ожидающие перезагрузки) до любых модификаций. Формат снимка: `SchemaVersion 11`.
- **Каждое изменение обратимо.** Перед изменением любого значения его исходное состояние записывается в `state.json`. Режим Rollback восстанавливает систему точно по записям — без догадок и «значений по умолчанию».
- **Никаких недоказуемых обещаний.** Скрипт никогда не обещает прирост FPS или снижение задержки ввода. Вместо этого он измеряет то, что может (загрузку CPU, память, диски, пинг) до и после, и точно объясняет, как самостоятельно замерить игровую производительность правильными инструментами.

Что скрипт сознательно **не** делает: массовый «деблоат», недокументированную магию реестра, изменения драйверов/прошивок и всё, что нельзя автоматически откатить.

## 2. Ключевые функции и модули

### Аудит и Rule Evaluator

Полный аудит только для чтения с **19 автоматическими диагностическими правилами**, каждое из которых выдаёт находку с доказательствами, оценкой достоверности и способом проверки исправления:

| Область | Правила |
|---|---|
| Система | `SYS-REBOOT-MARKER` |
| CPU / RAM | `CPU-HIGH-LOAD-SAMPLE`, `RAM-MEMORY-PRESSURE`, `RAM-XMP-DISABLED` |
| Диск | `DISK-LOW-FREE-SPACE`, `DISK-HEALTH`, `DISK-TRIM-DISABLED` |
| Сеть | `NET-ICMP-TIMEOUT`, `NET-WIFI-WEAK-SIGNAL` |
| Питание | `PWR-PCIE-ASPM-ENABLED`, `PWR-USB-SELECTIVE-SUSPEND-ENABLED`, `PWR-CPU-BOOST-DISABLED` |
| Службы | `SVC-DIAGTRACK-RUNNING`, `SVC-SYSMAIN-SSD` |
| Автозагрузка | `STARTUP-COUNT-HIGH` |
| GPU / Игры | `GPU-NO-HIGH-PERF-APPS`, `GPU-DRIVER-OLD`, `GAME-MODE-DISABLED` |
| Безопасность | `SEC-HVCI-ENABLED` |

Все находки носят информационный характер; во время аудита ничто не исправляется автоматически.

### Пресеты оптимизации

Пресеты заменяют длинные списки ручных флагов. Явно переданные параметры всегда имеют приоритет над пресетом.

| Пресет | Состав |
|---|---|
| `Minimal` | Только мягкие безопасные твики: телеметрия, фоновые приложения, Game DVR, советы/реклама, обслуживание дисков |
| `Gaming` | Полный стандартный набор шагов + отключение акселерации мыши, `-DisableNagle`, SysMain |
| `Full` | Gaming + сжатие памяти, индексация поиска, гибернация, уведомления, компоновка панели задач, геолокация, беспроводной дисплей |

Необратимые операции (удаление приложений, очистка, удаление OneDrive, установка рантаймов) **никогда** не входят ни в один пресет — для них всегда требуются явные флаги.

### Оптимизация сети

Опциональный шаг `-DisableNagle`: устанавливает `TcpAckFrequency=1`, `TCPNoDelay=1`, `TcpDelAckTicks=0` на всех активных физических адаптерах. Исходные значения сохраняются для отката, а изменение проверяется после применения. Эффект измерим встроенным бенчмарком пинга/джиттера.

### Отчётность

- **JSON**-отчёт аудита — полный машиночитаемый снимок.
- **HTML**-отчёт аудита (`audit-*.html`) — те же данные в виде аккуратной страницы с тёмной темой.
- **Отчёт о применённых изменениях** (`changes-*.json`) — всё, что изменил Apply, с исходными значениями и результатами по шагам.
- **Консольные сводки** в конце каждого запуска: разница бенчмарков, результаты верификации, обзор применённых изменений.

### Бенчмарк и отслеживание

- Каждый запуск Apply снимает метрики (загрузка CPU, RAM, свободное место на дисках, задержка/потери пинга, активная схема питания) **до** первого изменения и **после** последнего, затем выводит сравнение с шумовыми порогами — мелкие случайные колебания помечаются как «без значимых изменений», а не как улучшение.
- `-Mode Compare` сравнивает текущее состояние системы с сохранённым baseline и показывает историю всех сохранённых замеров.

### Верификация

После каждого ключевого шага Apply повторно читает параметр и подтверждает, что значение действительно применилось. **11 проверяемых шагов:** телеметрия, фоновые приложения, схема питания, SysMain, сжатие памяти, Game DVR, акселерация мыши, Nagle, сетевой троттлинг, индексация поиска, ручные обновления. Сбои записываются как предупреждения и перечисляются в итоговой сводке.

## 3. Режимы выполнения

| Режим | Назначение | Нужен админ | Пишет на диск |
|---|---|---|---|
| `Report` | Быстрый читаемый обзор системы в консоли (режим по умолчанию) | Нет | Нет |
| `Audit` | Полный снимок + оценка правил, сохраняет JSON + HTML | Нет | Только папка отчётов |
| `WhatIf` | Пробный прогон: показывает, какие шаги *выполнились бы*, с описаниями | Нет | Нет |
| `Apply` | Применяет выбранные оптимизации с бэкапами, верификацией и бенчмарком | **Да** | Да (state, лог, отчёты) |
| `Compare` | Сравнивает текущие метрики с baseline из Apply + история | Нет | Нет |
| `Rollback` | Восстанавливает все записанные исходные значения из `state.json` | **Да** | Да |
| `Startup` | Список записей автозагрузки (реестр, папка, задачи входа) с издателями; `-StartupAction Disable/Enable -StartupName X` управляет ими обратимо | Только для изменений | Только для изменений |
| `Components` | Просмотр/включение/отключение компонентов и возможностей Windows с откатом (`-ComponentAction`, `-ComponentName`) | **Да** | Да |
| `Repair` | DISM `CheckHealth` / `ScanHealth` / `RestoreHealth` (+ SFC) через `-RepairAction` | **Да** | Только лог |

## 4. Быстрый старт и примеры

```powershell
# Превью того, что произойдёт — ничего не изменяется
.\optimize.ps1 -Mode WhatIf -Preset Gaming

# Полный аудит только для чтения с 19 правилами (JSON + HTML отчёты)
.\optimize.ps1 -Mode Audit

# Применение пресета Gaming (требуется PowerShell от администратора)
.\optimize.ps1 -Mode Apply -Preset Gaming

# Сравнение текущего состояния с baseline, снятым до Apply (например, после перезагрузки)
.\optimize.ps1 -Mode Compare

# Отмена всех записанных изменений
.\optimize.ps1 -Mode Rollback
```

Дополнительные примеры:

```powershell
# Управление автозагрузкой
.\optimize.ps1 -Mode Startup
.\optimize.ps1 -Mode Startup -StartupAction Disable -StartupName 'OneDrive'

# Компоненты Windows
.\optimize.ps1 -Mode Components -ComponentShowAll
.\optimize.ps1 -Mode Components -ComponentAction Disable -ComponentName 'Printing-XPSServices-Features'

# Восстановление системных файлов (по нарастающим уровням)
.\optimize.ps1 -Mode Repair                          # быстрая проверка
.\optimize.ps1 -Mode Repair -RepairAction Restore    # полный проход DISM + SFC
```

## 5. Безопасность, обратимость и пути хранения

### `%ProgramData%\WinOptimize\` (общая для машины, пишут только изменяющие режимы)

| Путь | Назначение |
|---|---|
| `state.json` | База данных отката: каждое исходное значение до изменения |
| `optimize.log` | Журнал всех операций Apply/Rollback с метками времени |
| `benchmarks\benchmark-*.json` | Снимки метрик «до/после» для режима Compare |
| `reports\changes-*.json` | Отчёты о применённых изменениях |

### `%LOCALAPPDATA%\WinOptimize\Reports\` (на пользователя, пишет Audit)

| Путь | Назначение |
|---|---|
| `audit-*.json` | Полный снимок аудита (схема v11) |
| `audit-*.html` | Тот же аудит в виде читаемой страницы с тёмной темой |

### Как `state.json` гарантирует точный откат 1 в 1

1. **До** изменения значения его исходные данные (значение реестра + тип + флаг существования, режим запуска службы, состояние задачи, индексы питания, байты автозагрузки, состояние компонента и т.д.) добавляются в `state.json`, который сохраняется **атомарно** (временный файл + `File.Replace`, поэтому сбой не может его повредить).
2. `Rollback` воспроизводит записанные оригиналы, запись за записью. Записи, которые не удалось восстановить, **остаются в файле**, чтобы следующий Rollback мог повторить попытку; перед откатом автоматически создаётся резервная копия состояния. Файл состояния удаляется только когда все записи восстановлены чисто.
3. Если `state.json` не читается или повреждён, скрипт **отказывается продолжать**, а не теряет данные отката молча.

Операции, которые необратимы по своей природе (удаление временных файлов, удаление пакетов Appx, удаление OneDrive, установка рантаймов), явно перечислены в логе, в итоговом отчёте и никогда не входят в пресеты.

## Требования

- Windows 10/11, Windows PowerShell 5.1+ (синтаксис PowerShell 7 не используется).
- Консоль с правами администратора только для `Apply`, `Rollback`, `Components`, `Repair` и изменений автозагрузки.

## Как измерить реальный эффект

WinOptimize не измеряет FPS или задержку ввода и не заявляет о приростах. Чтобы измерить реальное влияние на игры: захватите frametime с помощью **CapFrameX** или **PresentMon** в одной и той же игровой сцене (60+ секунд) до и после применения изменений, затем сравните средний FPS и 1% low.
